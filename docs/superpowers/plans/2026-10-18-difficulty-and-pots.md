# Seven difficulty levels, a smarter Gardener, and flower pots — Plan

Spec sections: `docs/superpowers/specs/2026-10-18-map-v2-design.md` ("Difficulty levels", "Flower pots", "Looping sounds"). TDD where testable, one commit per step, `npm test` green after each, never push (main auto-deploys), dev server on port 8087 only.

## Steps

1. **Alarm bug (looping sounds).** Root cause: the fridge alarm level came from `snap.fridge.n`, which the sim freezes once the round ends (zombies were at the fridge when they won), and the "not in a round" branch stopped the tool loops but never the alarm; `leaveGameView()` only stopped the mower. Mower engine / tool / squeak loops had the same hole (`using`, mower `driving` and the wheelbarrow keep their last state after the round ends). Fix: `client/soundstate.js` (`loopsAllowed`, `alarmTarget`, `LoopMixer`) is the only thing that talks to the loop sounds; it silences everything the moment the phase is not `playing`, on leaving a lobby and on disconnect, and cannot restart outside `playing`. `Sound.stopAll()` kills gains at once. The server also zeroes `fridge.n` and every `using` flag when a round ends. Unit test with a fake sound.
2. **Seven levels.** `config.difficulties` becomes an ordered, data-driven table (`easy, normal, hard, veryhard, expert, nightmare, insane`): zombie-side knobs (aim error, reaction, fire scale, wave base/step, speed scale, lead shots, route smartness, coordination on the weakest door, errand / mower / tool chances) and Gardener knobs (see 4). `DIFFICULTIES`, lobby validation, the create form, the waiting-room host options and the lobby list (labels) all read the table. Old `easy` / `normal` ids stay and keep today's numbers.
3. **Pots.** A pot is a build kind (`builds.plant[]`, `pot: true`, 25 sunshine, HP, own cap of 10 per player) so it reuses the build input (`build`, `bx`, `bz`, `buildSeq`), the cover piece (HP, damage, break, `mapState` for late joiners) and the client ghost. Rules (`server/sim/pots.js`, mirrored in `client/map.js`): on the interior floor of the living room / kitchen / hall, never in front of a door or an interior doorway, never within 1.5 m of the fridge spot, at least 2 m from another pot (so a ring of pots can never wall a room off). A pot adds a dynamic garden slot to `game.slots`; any unlocked plant can be planted in it (`tryPlant`) and levelled up (`tryUpgrade`); when the pot breaks the plant dies with it. Client: terracotta pot model, ghost, `P` shortcut + 4th build-wheel entry + touch POT button, prompts ("Pots 3/10"), planting prompt/ring for pots.
4. **Gardener.** `bots.js` gardener brain rewritten as a planner scaled by the level table: door threat/defence map, plant mix by distance band (long range back, short range front, Wall-nuts at chokepoints), unlock tiers over time, upgrades into the most threatened plot, forts across the approaches, repair/replant, pots + plants around the kitchen when a door falls, retreat to defend the fridge, lead + headshot aim, strafing, sun pickup. Expert and up field a second Gardener (documented in the spec).
5. **Zombie bots.** The same table drives route smartness (spawn-time door choice weighted to the weakest door, a per-wave focus door that a share of the wave follows), tool / mower / errand chances, speed, lead shots. Balance-harness zombie kids use a fixed skill profile so Gardener difficulty can be measured on its own.
6. **Balance.** `scripts/balance-lib.mjs` gets scenarios for all seven levels (afk, decent, versus, zraid), `scripts/balance.mjs` prints a table; `test/balance.test.js` adds loose monotonicity guard-rails. Tune the table until the ordering holds.
7. **Docs.** Spec sections (levels, pots, sounds), README (levels, pot control).
8. **Verify.** `npm test`, `node --check client/*.js`, headless Chromium desktop + phone on port 8087: create an Insane lobby, alarm stops at match end, place a pot in the kitchen and plant in it, no console errors.
