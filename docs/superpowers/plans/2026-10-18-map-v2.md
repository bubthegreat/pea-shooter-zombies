# Map v2: The Big Backyard — Implementation Plan

Spec: `docs/superpowers/specs/2026-10-18-map-v2-design.md`. Mechanics from the main spec ("Playtest changes", "Plant upgrades") stay.
TDD, seven phases, one or more commits per phase, `npm test` green after each. Never push (main auto-deploys).

## Shape of the change

Server sim stays pure. New modules in `server/sim/`:

| Module | Job |
|---|---|
| `world.js` | Layout constants only: bounds, gate/pen, house, garage, rooms, doors, plots (`gardenSlots()`), fridge, spawns, shed, cellar, deck. |
| `terrain.js` | Deterministic heightmap grid (hills, mounds, creek, pads, cellar pit), 1 m cells, cm-quantised. `terrainHeight(x,z)` samples it with the **same triangulation the client mesh uses**. `terrainData()` = base64 int16 for the welcome message. |
| `map.js` | `MAP`: static colliders (walls, interior walls, furniture, deck/steps, terraces, bridge, cellar shell), doors, destructible cover list (seeded layout), part spots, nav graph + the three routes. Pure data, built once at import. |
| `collide.js` | `Field` (4 m spatial hash of colliders: box and cylinder, each with `y0..y1`), `STEP`. `resolve()` pushes a circle out, `groundAt()` = terrain + any collider top within `STEP` of the feet, `segment()` = first hit for projectiles/LOS. `clampToWorld()` (static only). |
| `cover.js` | Per-round destructible state on a `Field`: cover pieces, doors, builds (hp, damage, break, brains for zombies, debris events), `mapState()` for late joiners. |
| `build.js` | `tryBuild()`: build kinds, validation (grid, bounds, no-build zones, doorway zones, plots, overlap, cap), cost in sunshine or brains. |
| `parts.js` | Mower parts: spawn at random part spots, pick up / drop / install, powered tools, mower parts mask. |
| `nav.js` | Dijkstra tables over the waypoint graph, `planPath()`; bot route choice (front lawn / left gravel / right hedge). |

Changed: `game.js` (field, terrain-aware movement, head start hold, fridge, round reset), `combat.js` (terrain + cover hits, brains, part drops), `bots.js` (routes, doors, fridge, errands, cover stuck-handling, LOS), `garden.js` (turret LOS, plots), `rules.js` (fridge win, head start, no garden-wipe win), `mower.js`/`equipment.js` (parts gating, new garage coordinates), `config.js` (all tunables + `publicConfig.map`), `lobby.js` (welcome carries `state: game.mapState()`).

### Protocol

- `welcome.config.map` = static map once: `terrain {cell,x0,z0,nx,nz,data}`, `statics [{id,s:'box'|'cyl',…,y0,y1,style}]`, `cover [{id,kind,s,x,z,…,y0,y1,rot}]`, `doors`, `plots`, `fridge`, `rooms`, `house`, `garage`, `shed`, `deck`, `cellar`, `creek`, `paths`, `partSpots`. `welcome.state = mapState()` = `{round, gone:[ids], hurt:{id:hp}, builds:[…]}` for late joiners / reconnects.
- Snapshot adds `round`, `headStart` (s left, 0 = released), `fridge {m (0..1), n (zombies at it)}`; entities gain `carry` (part held), `parts` (mower mask), `powered` (rack item), `partKind` (`part` entities), `brains` (zombie kids). Cover / door / build changes travel as events: `coverHit {id,hp}` (at 75/50/25 %), `coverBreak {id,kind,x,y,z}`, `build {id,kind,x,z,rot,by,hp}`, `buildFail {by,reason}`, `partTake`, `partDrop`, `install`, `fridgeAlarm`. A changed `snap.round` means the client resets all cover/build state.
- Input adds `build` (1-based index into the team's build list, 0 = none), `bx`, `bz` (grid cell), `br` (0/1), `buildSeq` (same sequencing idea as `plantSeq`). Messages stay under the 4 KB cap.

### Coordinates (m; Y up; yaw 0 faces -z; zombies enter from -z)

Yard x -40..40, z -52..46. Gate/pen z -52..-47, x -16..16. House x -14..8, z 6..24 (living -14..-6, kitchen -6..2, hall 2..8; E-W doorways at z 15). Garage x 8..20, z 8..22 (hall doorway at x 8). Doors: front (x 5, z 6, out -z), back (x 5, z 24, out +z, deck behind), side (x -14, z 15, out -x), garage (x 20, z 15, 5 m, out +x). Fridge in the kitchen against the back wall (-2, 23.3). Four plots of 4x4 slots, 3.5 m apart, rows outer->inner Peashooter / Cactus / Cactus / Peashooter. Ledges ~1 m: deck 0.9 with steps, terraces 1.0, stone retaining walls; STEP 0.5, jump apex 1.0.

### Rules of thumb

- Doors: HP, `passTeam:'plant'` (plants walk and shoot through; zombies are blocked; zombie shots hurt it). Broken door = collider gone, stays gone for the round.
- Cover blocks walking when its top is above feet+STEP (lower ones are stood on), blocks every projectile, takes damage from any projectile whose team does not own it (turret peas included). Splash damages cover.
- Fridge meter: `+ min(n,4) / fillSeconds` per second for the n living zombies within `radius` of the open fridge in the kitchen; never drains; meter 1 = zombies win. Garden-wipe win removed.
- Head start: `headStart = 15` at round start. Zombies (bots and kids) are held in the pen and cannot fire; wave times are shifted by it. Plants start with 300 sunshine, nothing planted (`features.initialGarden` default false).

## Phases

### P1 Terrain, collision, house, doors, routes
1. `terrain.js` + tests: deterministic, grid round-trips base64, flat pads under house/plots/pen, hills > 2 m, creek < 0, bridge deck walkable.
2. `world.js`, `map.js`, `collide.js` + tests: statics do not overlap walls wrongly, every door/doorway has a clear 1.5 m corridor, `resolve` slides along walls and stops at doors, `segment` hits walls/doors, ledge needs a jump, `groundAt` stands on deck/steps.
3. `Game`: field per game, `_moveActor` uses `resolve`/`groundAt`/gravity (jump onto a 1 m ledge), spawn y from terrain, projectiles stop at terrain and colliders (`combat.js`), suns/mower/rack follow new coordinates. Update every layout-dependent test.
4. `cover.js` doors only: HP, break, events, `passTeam`; zombie shots break a door; plant shots pass.
5. `nav.js` + `bots.js`: route choice (front 40 % / left 30 % / right 30 %), door attack, fridge goal, stuck handling; a bot test per route reaching the fridge with doors broken.
6. `config.publicConfig().map` + `mapState()` in `welcome`.

### P2 Garden plots, head start, Fridge Meter
Plots live in `world.js` from P1 (`gardenSlots()` 64 slots, any plant any slot). P2: `initialGarden` default off, `startSunshine 300`, head start hold + wave shift + `snap.headStart`, fridge meter + `snap.fridge`, win rules (zombie win only by fridge), Gardener walks via the nav graph and plants plot by plot, turret LOS. Tests: rules, held zombies, meter maths, win.

### P3 Destructible cover
Seeded layout (gravestones, rocks, trees, hedges, trash cans, picnic table, kiddie pool, shed walls) in `map.js`; `cover.js` piece HP from `config.cover[kind]`, damage by projectiles/splash/tools, `coverBreak`, `mapState`. Tests: block shots, break, stay broken, rocks tougher than stones, layout never in no-build zones, bots stuck-handling reaches the fridge through a graveyard.

### P4 Fortifications
`build.js` + input fields + brains economy (zombie +5 per hit, +10 per turret). Kinds: Hedge Wall (sun 20, hp 60), Wooden Fence (sun 45, hp 150), Wall-nut stays a plant; Tombstone Wall (brains 25), Junk Barricade (brains 10), Trash-can Tower (brains 15). Cap 12 per player. Tests: grid snap, rotation, cost, cap, no doorway/plot/overlap, destroyed builds free a slot, brains.

### P5 Mower parts
`parts.js`: 3 batteries, 2 gas cans, 1 spark plug at random spots per round; E picks up (one at a time) / installs at rack hook or mower; powered tools; mower needs all three; hit on a carrier drops the part. Tests for each rule + bot errand.

### P6 Client
`scene.js` rebuilt from `config.map`: terrain mesh + painted paths, house/garage/interior, deck, cellar, shed, instanced cover, builds, doors with planks, fridge with open door + glow, parts; `main.js` ground-aware, build mode (B, wheel, ghost on 1 m grid, R rotate, click/tap place), prompts; HUD (fridge snack bar + alarm, head-start countdown, brains, part checklist, build wheel); touch (Build, Rotate/Place); loading-screen rules. Budget: merged terrain + instanced cover, report draw calls / triangles.

### P7 Balance
`scripts/balance.mjs` scenarios: afk plant, active plant, zombie kid front/left/right/fridge rush, versus. Targets: decent kid wins Easy mostly; bots use all three routes; fridge win reachable by an AFK defence; versus roughly even. Rewrite `test/balance.test.js`.

## Verification
`npm test`; `node --check` on client modules; headless Chromium on :8088, desktop + phone emulation through lobby to game (walk terrain, jump ledge, plant during head start, break a door, reach fridge, build a fort, pick up a part), no console errors, draw calls and triangles reported.
